DIRECTION (proposed on branch work/lockstep-direction; binding once merged)
Deterministic lockstep is the product path. Every client simulates the whole
universe; only player inputs travel. This is the only design that can reach a
shared economy, missions and NPC AI without replicating each system separately.
The replica path (x4lan relay, UMOVE/NPC replicas, 7.5.x packages) is frozen:
bug fixes only, no new replica features. Its accepted human results (cargo/magnet,
Cooperative Trial, radar, PvP/NPC kills, kill mission, docking/ship exchange; see
reports/PLAYTEST-7.5.0-20261025.txt) stay valid for 7.5.x and remain the
regression baseline until a lockstep package replaces it.
Ownership is unchanged: owner Lith7ium, technical lead Ferrite (AGENTS.md).

V1 SCOPE AND PLAN
v1 = two players, Windows-Windows, one fixed play profile, start from the known
snapshot. In order:
1. Consolidate: one named play profile replaces the overlay-of-the-day; every
   default-off key either joins it or gets a removal date. Move runtime code
   (probe, relay) from tools/dev to src/.
2. Two physical PCs over the internet, ideally Intel + AMD, 1-2 hours. Approximate
   rcpss/rsqrtss results differ by CPU vendor; the census still lists 63 more
   sites. This test outranks Linux work.
3. Mid-game save -> transfer -> load -> in sync. One mechanism gives join in
   progress, desync recovery and persistence between sessions.
4. Record inputs + snapshot per session; replay offline after each gate change
   and compare per-tick hashes; automate first-divergence bisection.
5. UI replay coverage as an explicit covered/missing list of player actions.
Code health alongside: split the header-implemented unity build into .c units;
move RVAs/hashes into a per-build profile; prefer signature resolution so an
Egosoft patch does not break ~1.4k addresses at once.
