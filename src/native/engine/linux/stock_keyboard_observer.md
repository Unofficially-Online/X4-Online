# Linux stock keyboard observer

The default observer is an opt-in development diagnostic. It observes the selected stock handler calls and forwards each call once with its original arguments. A separate, explicitly enabled keyboard replay diagnostic can attach a consumer that suppresses selected local calls; the status then reports `capture_suppressed`. This mode is experimental and does not provide independent player controllers. It wraps only STATE 2–9, 13–16 and 18–19, plus ACTION 0x7b; other handlers and SPACE are untouched. Raw event records identify the calling thread and return address. Overflow or concurrent ring contention increments a visible counter; the observed sequence is not a complete stock input record.

The embedding translation unit owns the one static session for the process lifetime. Before `sko_begin`, validate the exact ELF and map the owner pointer and original handlers to their verified runtime addresses. `verify_pins` must recheck the full identity and original function pins, and must bind the supplied addresses to those pins. The injected read and aligned pointer-CAS callbacks must be fault-aware; `SKO_CAS_UNKNOWN` means a write may have occurred. Original-call callbacks must invoke the supplied pinned original exactly once with the native typed ABI and remain resident for all possible late wrappers. The wrapper preserves errno across recording and after the original call. No wrapper may outlive this code or callback state.

Call `sko_begin`, `sko_install`, `sko_validate`, `sko_drain`, `sko_get_status` and `sko_restore` only from the proven serialized owner-thread boundary. Passing `quiescent=1` is the caller's assertion that no dispatch has loaded or can load an old node handler, no input-table writer runs, and no management call is reentrant. A zero wrapper depth is necessary but does not prove this guarantee: a thread may have loaded a handler without entering it yet. Installation first prepares metadata, then checks and swaps one pointer at a time; failed installation attempts owned rollback. Recording starts only after all swaps and readbacks succeed. Restore disables recording first, checks depth, rediscovers the current tree, restores only owned wrappers with CAS, and verifies readback. A missing/recycled node, changed owner/topology or foreign handler fails closed with retained obligations. Unknown writes are not inferred successful or safely discharged merely because an original appears later.

The complete reachable action/state/range trees are bounded and structurally checked before each modification. Selected handler identities must match the initial census; unrelated tree growth is permitted when every selected node and handler remains unchanged. A saved node address is an identity value, never a dereference target; the CAS target comes from the latest census. Structural snapshots cannot detect same-address reuse or a transient modification that occurs between checks. A real integration must independently prove table quiescence and an epoch/lifetime boundary throughout management; do not treat this code as supplying that proof. Validate at every safe boundary and stop trusting observations after invalidation. Keep the metadata and code loaded even if restoration succeeds because a previously loaded wrapper may still run.

The default-off native adapter is `gate_stock_keyboard_observer.h`. The Linux live-test builder enables it only with `--stock-keyboard-observer` and an isolated snapshot. The request pins the accepted native worker thread after loading; a thread migration is not required. Installation occurs at the next main-thread admission after the previous worker frame completed. The native in-flight/loading flags and the flag that permits bypassing the worker join must be clear. The whole input-update wrapper then establishes the boundary for worker-side inspection and cleanup. Both the vtable pointer and its page protection remain owned cleanup obligations until verified restored.

Synthetic tests cover refusal and cleanup paths, including failed page-protection restoration. The offline ELF checker verifies a private byte copy only. A retained two-instance native Linux run on 10 November 2026 observed all 180 requested ticks, installed at tick 2, and restored every owned pointer at STOP. It contained no keyboard events. That result establishes the bounded idle installation and cleanup path; it does not establish event coverage, input suppression, delayed replay, or playable multiplayer.

A later bounded two-instance native Linux test at `ff99d181` replayed four synthetic Left/Right press/release events at the same two-tick delay on both peers. All 600 reported ship poses matched, with 78 distinct yaw samples. Both peers restored their owned hooks and ended with no held keys. This tested one shared canonical ship; the second input slot was neutral. Existing degraded world-identity diagnostics remained, so this does not establish complete universe or Windows/Linux parity.

The independent audit confirmed those facts against the raw engine logs, but rejected the old processed-log artifacts because they omitted shutdown rows. The future-run collector now derives processed evidence from a retained engine log after all owned writers close; historical captures remain unchanged.

The separate `--player-reference-probe` inspects the canonical Player's reference metadata at the worker boundary. It makes no reference-management calls and reports `lifetime_contract_pending`; an observed count is not a lifetime guarantee or permission to create a second Player.
