# P2 PlayerController route helper

This standalone helper is not wired into X4. It supports a single P2 controller and copies all 79 Linux virtual entries and both Itanium ABI header words. Slots 13/14/17 route transform/velocity/acceleration to stock on the owning thread inside its scope, otherwise to the agent or player adapter. The cached global predicate is autopilot OR (no flight control AND assist(0) AND no highway); the accessor reads the held ship flag on every off-scope motion call, and a clear flag also selects the agent adapter. Slots 21/30/56/57 route smoothed throttle, no-highway, assist, and agent mode to stock in that scope and to the snapshot outside it. The canonical controller retains its original table. Snapshot publication is atomic; the scope marker is thread-local.

`gate_player_controller_native_motion.h` supplies actual generated Linux x86-64 false-branch trampolines and exact native Agent wrapper addresses. It copies each ELF prologue up to its predicate call, restores the original time register, and jumps to the false continuation. The Agent 17 implementation's null, add/replace, selector and output behavior were compared against the PlayerController true branch. The builder rejects unexpected prologue bytes. `player_native_bind` assigns native addresses using the ELF load bias, and requires external validation and W^X buffer management. The owner supplies the cached global predicate and a verified accessor that confirms controller+0x20 equals the held ship, then reads its +0xd1 flag. The owner holds the ship alive for the entire routing lifetime; a failed read or identity check leaves the output untouched, increments access_failures, and requires the owner to stop; missing adapters refuse installation. Native scoped lifecycle callbacks 40/41/42/43 remain original and are not ported; existing off-scope getters, pathing and renderer consumers are unclassified. The helper does not pin or inspect a native image. A future adapter must verify the full executable image SHA-256 `113f73d74570084f6ce18a659b365009eccf579fb66dbabb5dad2b1718045f20`, relocated table words, and the actual adapter code and call sites before use; the six complete FDE hashes are provided in the native motion header. Neither bind nor install checks those hashes: the native caller must enforce them before use. Scope entry alone does not establish exclusive access to the global bank, context tree, player singleton or object lifetime. The integrator must supply the verified boundary, stable controller and storage lifetime, and quiescence of all table readers around install and restore. There is no generic exception recovery here. Seat vector and pilot-post handling belong to the lifecycle owner and are untouched.

Only static mapping and a synthetic fixture have been checked. Run `cc -std=c11 -Wall -Wextra -Werror -pthread src/native/engine/linux/test_player_controller_routes.c -o /tmp/x4-player-controller-routes-test && /tmp/x4-player-controller-routes-test`. This exercises the SysV floating-point time argument, the mode byte and output buffers, separate canonical and P2 tables, foreign-thread routing while a P2 scope is open, coherent snapshots, live flag changes, wrong-ship refusal, missing-adapter rejection and vtable restoration. It does not launch X4 or validate native execution.

Test the actual emitted prologue adapters with `cc -std=c11 -Wall -Wextra -Werror src/native/engine/linux/test_player_controller_native_motion.c -o /tmp/x4-native-motion-test && /tmp/x4-native-motion-test`. The synthetic continuations inspect the register and stack state, including the XMM0/XMM5 time reload and the ELF prefix rejection. They do not execute native engine code. The copied stack prologues have no independent unwind metadata; this is suitable only under an externally established no-unwind contract, and stack unwinding across a generated stub is unresolved.
