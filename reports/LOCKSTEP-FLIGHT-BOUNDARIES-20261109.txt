LINUX / WINDOWS STEERING BOUNDARY COMPARISON
9 November 2026

Result
  The 120-tick comparison reproduces the remaining physical-state mismatch at
  tick 98. It does not establish cross-platform determinism. New read-only
  snapshots narrow the investigation to earlier movement requests: actor 1's
  linear command first differs at tick 93, its rounded request target first
  differs at tick 96, and its physical velocity first differs at tick 98.
  This ordering is evidence for further investigation, not proof of causality.

Diagnostic change
  Existing Steering wrappers now sample the model's three-lane linear/angular
  commands after the original update, plus the solver's request groups before
  and after it. They retain raw rounded/scaled targets, gains and dirty flags.
  Every read has validity bits; failed or unstable-pointer reads are invalid
  rather than interchangeable with numerical zero. No allocating engine getter
  is called. Raw pointers are not exported. The original update runs once;
  Linux errno and Windows last-error are preserved across the new reads.

  These are last-call snapshots, not all invocations or actual call arguments.
  Pointer rechecks do not prove atomic/coherent state, lifetime or ABA safety.
  The existing serial fixture path and frame-boundary reads limit this evidence.
  The diagnostic does not add a numerical correction or replay player inputs.

  (Linux versus Windows); the corresponding scaled request differs too. The
  rounded angular target remains equal. Tick 76 retains that difference in the
  before snapshot; the after snapshot agrees again.

  Actor 1, tick 93: linear command Z is 4286e47e versus 4286e47c, approximately

  All 1,428 captured STATE rows per platform, ticks 2 through 120 for twelve
  actors, are byte-identical to the corresponding prefix of the earlier
  600-tick run. This bounds the observed diagnostic effect to those fields;
  it is not proof that every engine behavior was unaffected.
