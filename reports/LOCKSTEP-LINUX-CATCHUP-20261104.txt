LINUX CATCH-UP: THE LINUX GATE AGAINST THE CURRENT SESSION DEFAULTS
4 November 2026 | branch contrib/ferrite-linux-catchup | roadmap 12 (Windows/Linux) and 13 (a Linux server)

WHY
The Linux gate last changed on 1 November; the Windows session defaults (tools/dev/native_gate_defaults.lua,
174 ON entries) have grown since. The Windows-vs-Linux comparison stopped at 1200 ticks because the 1 November
measurement config is not self-consistent past ~1200-1800 even on one platform (census report, 3 November).
Goal of this branch: the Linux gate runs the Windows defaults' determinism stack, then the people stack.

THE GAP (smoke 15aa54ca)
  Lua methods: Windows gate 663, Linux gate 121.
  Pinned Windows engine sites (tools/dev/lockstep_linux_map.py --disasm, rebuilt today): 1282, of which 433 have a
  high or verified Linux candidate. Families without a Linux port: the battle scope's fixture state (strict_state,
  shield_refresh, strict_physics, order/fleet state), actor-keyed RNG (flight, steering, radar, agent/spline, ship,
  weapon, nav, death, bullet, shape), the view-point family (~25 keys), and the people stack (pilot inputs, UI replay,
  on foot, prediction, render frames).

A DESKTOP LINUX HOST (2e162ed9)
tools/dev/linux_gate_live.py run assumed the VPS layout. --game, --steam-home and --shm name a desktop host's Steam
library, the running client's .steam and its shared memory; with snap Steam the client keeps that in
/dev/shm/snap.steam, so it is bound over /dev/shm in each X4's namespace (X4 runs outside the snap and reaches the
client). --discard-layer names a locally built X4MP discard layer (src/native/vk-discard). On a desktop host with
24 cores, 600 ticks with load take ~85 s and 6000 ticks ~6 min (the VPS took many times that).

THE PORTS (each: the shared header keeps its domain, seeds, counters and status under a *_OWN_PLATFORM guard, so a
Linux draw seeds exactly as on Windows; the Windows preprocessed lockstep_gate.c is byte-identical, zig cc -E -P)
  weapon_fire_rng (linux/gate_weapon_fire.h): the shot 0x1138c70 in slot +0x1fc0 of U::Weapon 0x3c6a440 and
    U::Turret 0x3d38dd8 (Windows +0x1f30), the fire loop 0x1d698b0 its only caller; System V signature with the base
    time in xmm0, a float in xmm1 and four stack qwords.
  engine_refresh_rng (linux/gate_engine_rng.h): the listener 0x14382f0; GCC inlined FloatRange, so the aligned word
    at 0x1438348 jumps to a stub that steps either the Windows keyed state ((tick, key), or (tick, the class's
    Windows vtable RVA) for a ship without a key) or the thread's word natively. The step, the 2^-32 scale and 8.0
    are Windows' own; Linux's "+ itself" equals Windows' "* 2.0".
  Tests: linux/test_gate_weapon_fire.h, linux/test_gate_engine_rng.h (the stub's machine code is run against a
  landing pad); check_lockstep_gate_linux.py --x4 PASS on the Linux host; site check 423 PASS.

  spline_join_all (linux/gate_spline_join.h): the update 0x1363de0 in slot +0x78 of the model 0x3b5d6b8; its
    pending requests are a libstdc++ deque at +0x468 (start.cur +0x478, finish.cur +0x498), the request's status
    +0xb8 read under the XLib::Mutex 0x3e76960; the calculator worker in 0x3e5b850 (running byte +0xb8). Boot
    option 2^35 installs the slot; gate.spline_join_all() arms the bounded wait (stop reason 58 on a failure).
    On Windows the same key needs the agent module (agent_full), so a Windows run cannot carry it alone yet.
