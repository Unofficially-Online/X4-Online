Bounded diagnostic additions
----------------------------
The default-off per-tick Nav watch uses the existing canonical motion/timing
serializer for at most four saved identities over an explicit bounded window.
It does not advance or rewrite census state. Its independent evidence parser
requires the complete ordered tick/identity set, validates canonical metadata,
cross-checks matching census preimages and hashes, and rejects failed cleanup.
Mandatory watch receipts bypass optional status thinning.

A separate default-off path-transform observer can compare the native cached
transform with a live-transform candidate inside ordered path jobs. It returns
the native result unchanged, but the additional engine getter may have side
effects. It is a diagnostic experiment, not a passive or production-safe fix.
Its native behaviour has not yet been validated. It excludes the overlapping
step-chain hook and fails closed on ownership, bounds or buffer failures.

Opt-in event RNG comparison
--------------------------
Source 18f3be5152e7373da8d1831c8168f32141e4a260 adds a Linux event-delivery
scope through the existing event-order redirect. The scope derives a private
RNG word from the admitted tick, portable source identity, event type and due
time, and restores the caller's word on normal return. It remains default-off.
The pinned ELF checks, synthetic native guards, 165 Lua bridge methods and 29
mock relay scenarios pass. Added cases cover nested restoration, foreign
threads, unreadable identities, ownership loss and explicit class-fallback
collisions. These checks do not replace native execution.

The first native comparison uses the same seed-2222222 snapshot, nav-key and
ordered pathing, launch order 2,1, full census every 120 ticks, and gate SHA256
980ee2a31badb83f60e047b7a7e44a9e227ad891233bec62d95cdefce60dc767.
Both peers complete 15000 ticks. All 126 full census captures agree across
the recorded domains, as do all 16004 motion-watch rows per peer from ticks
8000..12000. There are 544 successful watch/census comparisons per peer.
Both emit STOP completed=15000 reason=1 restored=1; manifest file hashes agree,
no owned X4 process remains, and the recorded Steam process is unchanged.
This is agreement of the recorded domains at the sampled times, not proof of
every internal engine state, mixed-platform play or a complete gameplay test.

The independently checked SCRIPT window 11360..11900 has 69815 rows per peer,
complete indices and all 541 matching closed tick tallies. Matched scope
contents, draw counts, PCs and scope order agree. Pilot 8b61b now calls
trade.find.free at ticks 11383, 11401, 11428, 11479 and 11518 with identical
rows on both peers. Neither calls it at 11396: scheduling changed, so this is
not a comparison of the identical failing invocation from the prior run.

The EVENT receipts are internally complete but are not identical between
peers. Cumulative counts/keyset/drawset first differ at tick 3601. The complete
all-delivery window 11360..11900 contains 36066 versus 36047 rows; no matched
delivery differs in its reported draw count. Outside that window only drawn
deliveries have rows, so the first cumulative split cannot identify every
extra zero-draw delivery. All 15000 status receipts have zero foreign-thread,
unreadable, unknown-draw and failure counts, with 53 class-fallback calls per
peer. Final call counts are 941261 versus 941259. The raw row does not contain
an observed exit word; reconstructed terminal words are not independent exit
observations. Sixteen adversarial parser checks pass.

Bounded RTTI inspection identifies the differing source/event RVAs as
U::BuildStorage and U::UpdateBuildEvent. The snapshot identifies the retained
source objects as build storages. The Windows build_rng hook already addresses
randomized load-time scheduling of these events. The Linux event scope starts
at admitted delivery and cannot retrospectively align timers created while
loading. This is the next candidate mechanism, not proof that the remaining
event differences are harmless or the only remaining source of divergence.

Native Linux vtable RVAs are seed inputs here. Same-ELF validation does not
establish seed parity with Windows. An unmapped source uses its class as a
fallback key; this is not a unique object identity. Native unwind recovery and
the thread safety of the pre-existing event-order batch are not established
by the new scope.
