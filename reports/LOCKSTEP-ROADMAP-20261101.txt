B. NETWORKING (rundown section "Latency")
 6. [later, only if 3 is not enough] Direct player-to-player input links: each client also sends its input
    record to the other players; a step uses whichever copy arrives first, checked against the relay's bundle;
    the relay stays the referee for timeouts, dropouts and checksums. Helps most when players are close to each
    other and far from the server. Costs: routers block direct links, players see each other's IP addresses.
 7. [offline done, live test open] Getting through home routers: UPnP/IGD port mapping where the router allows it; otherwise the
    relay introduces the two peers for UDP hole punching; a pair that cannot connect keeps using the relay. Branch
    contrib/ferrite-nat, report LOCKSTEP-NAT-TRAVERSAL-20261101.txt: C module for both gates (nat_link_path: direct / relay /
    pending), PCP -> NAT-PMP -> UPnP with lease and release, relay --rendezvous-port (NGNAT/1, own thread), NAT simulation.
    Simulated: all punchable pairs direct in <1.5 s; symmetric vs symmetric or port-restricted -> relay unless a port is mapped.
    Next: live plan section 9 (this PC <-> VPS), then wiring into B6.
