Linux lockstep performance investigation - 8 November 2026
=========================================================

Scope
-----
Two isolated Linux X4 9.00 (611726) instances on one Ryzen 7 7800X3D desktop,
hardware Vulkan rendering, the same owned snapshot (seed 2222222), reverse
launch order 2,1, 600 ticks per comparison and a full census at tick 1 and every
120 ticks. Ordered pathing remains OFF in these performance comparisons.
This is simulation validation, not a playable Linux client or a remote-peer test.

The scalar and accelerated comparisons capture exactly the same object fields,
identity list, unknown-field counters and per-domain SHA-256 values. No object
sampling, reduced census frequency, weaker digest or disabled validation is used.
Unknown motion fields remain outside the existing census coverage.

Measured cause and first improvements
-------------------------------------
Probe profiling now separates native world capture from per-object log output.
After the initial load, the scalar implementation spends about 950 ms scanning
and hashing the world and another 60 ms writing detailed rows. Ordinary relay
steps have a median near 16 ms in these short comparisons. Initial-census
logging has much greater volume and is reported separately by the raw profile.

The optional --world-log-mode hashes keeps every full world capture, bank record
and relay digest, but omits per-object diagnostic pages. Full logging remains the
default. Over 600 ticks, one client log shrank from about 291 MB to 19.5 MB;
the three measured steady capture-frame intervals had median 1050 ms with full
logging and 969 ms with hashes-only logging. This alone does not fix stutter.
Hashes-only logs cannot reconstruct an object-level divergence; retain full logs
or a targeted capture when investigating one.

The Linux SHA-256 implementation now selects SHA-NI and SSSE3 only after CPUID
checks, with the previous scalar implementation as fallback. The accelerated
function is separately compiled for its required instructions; the module does
not require a globally raised CPU target or a new system-library dependency.
The actual Zig/glibc-2.17 module confines SHA/SSSE3 instructions to that function.
The checksum implementation is original code. Instruction semantics were checked
against Intel's SHA extensions documentation:
https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sha-extensions.html

With SHA-NI and hashes-only logging, the full scan measured 411-429 ms across
the two instances, and the three steady capture-frame intervals had median
438 ms. All six WORLD_HASH rows of both instances exactly match the earlier
scalar/full-log control. Both peers stopped at tick 600 with restored=1;
Steam process identity was unchanged and no owned process remained.
This is a measured improvement, but the remaining periodic stall is visible.

An exact-byte leaf cache then reduced the steady capture-frame median to
398 ms (maximum 414 ms in the three measured intervals). Its 2.75 MiB table
uses a bounded sample only to choose a slot; a hit requires equal length and
every input byte to match. Allocation failure or oversized inputs hash directly.
All six full WORLD_HASH rows per peer still exactly match the scalar/full-log
control. Both peers again stopped at 600 with restored=1 and complete cleanup.
This remains a visible periodic stall; it is not described as playable.

Experimental distributed census
-------------------------------
A separate, opt-in WORLD_ROLLING_1 mode captures one deterministic range each
tick. It freezes a sorted identity cohort for 120 ticks and resolves each native
object again at its sampling tick. All four domain serializers, identity
rechecks, bank checks and unknown-field flags remain in use. This changes when
objects are sampled and is deliberately not presented as equivalent to the
instantaneous WORLD_IMPORTED_2 check. Full capture remains the default.

The first two-peer native run compared 600 matching slice states, completing
five cycles. Cohort sizes were 521658, 521673, 522197, 522537 and 522788;
521224 were imported identities. Both clients stopped at 600/restored=1, the
relay passed, Steam identity was unchanged and no owned process remained.
After tick 120, the 479 measured relay intervals had median 19.877 ms,
99th percentile 27.072 ms (nearest-rank method), and maximum 45.377 ms.
None exceeded 50 ms. At the former periodic capture boundaries the three
intervals had median 17.159 ms and maximum 21.302 ms. Ordinary steps are now
slightly more expensive, but the former 398-1050 ms periodic pauses are absent
in this short measurement. These are relay-step timings, not display-frame
timings or a human playability verdict. Startup is excluded: the first profile
window still includes a roughly 283-286 ms maximum probe call. Tick 600 is the
terminal report and has no released_at interval in the relay record.

Rolling samples are not an atomic whole-world snapshot. Newly created objects
may wait almost two cycles for their first sample; an object born and destroyed
between cycle boundaries may never enter this census at all. Creation-event
digests run separately. Unknown motion reached 1477 objects in a single slice;
unknown class and reference counters were zero in this run. Unmeasured state,
transient differences between samples, Windows interoperability and player
controls are not established. The known later motion divergence remains open.

The same new binary was also run in the original full-census mode for 600 ticks.
All six complete WORLD_HASH lines per client exactly match the original scalar
control. This validates that the shared range-scanning refactor retained that
control's full-capture output, independently of the new rolling semantics.
Both bundles retain gate SHA-256:
827c460da852efc91cf144f3443d5cafc1b8c9046248af3f2acd90a67935ef60.
Those two historical bundles were built with dirty source based on b3be9c8.
A subsequent build from clean commit a9e70aaa1eb30eb1a93d0ee3fe93d460de33b189
reproduced the exact same gate binary hash above. Their original manifests and
raw evidence are retained unchanged; this later reproduction identifies the
committed native source without rewriting the earlier provenance records.

Long rolling comparison (same committed native binary)
------------------------------------------------------
The 12,000-tick run completed 100 cycles and both clients stopped with restored=1.
It FAILS: the first differing rolling sample is tick 8473, exclusively in the
motion domain, with 477 differing samples in total. The first range is
[318598,323023), wholly within the 521224 imported identities. Summary-only
hashes cannot identify the individual differing object. Logged created-identity
event digests match on all 12000 common ticks; that is not movement equality.
The corrected evidence validator independently reproduces this failure.

After tick 120, 11879 relay intervals had median 24.031 ms, p99 34.331 ms
(nearest rank), and maximum 550.402 ms. There were 22 intervals above 50 ms.
At the old periodic capture boundaries, 98 intervals had median 25.4975 ms
and maximum 64.932 ms. Thus the regular full-census pauses are reduced, but
all stalls are not eliminated. The single 550 ms interval was tick 11082;
client 2's containing profile window reports maximum probe time 530.171 ms,
with the module/status stage elevated, while average world scan stayed near
3.62 ms. This localizes the remaining outlier to a different stage, without
proving the particular native call, logging or garbage-collection cause.
Without status thinning, DebugError calls execute inside the module stage;
log_us measures only the final flush, not all logging work. The suspect tick
has ordinary row volume, and these wall-time clocks also include descheduling.
Steam identity remained unchanged and no owned process remained.

Further diagnostic changes (native comparison pending)
-----------------------------------------------------
The existing status-stride mechanism is now exposed as --status-stride N in
the Linux bundle. It reduces intermediate module status output and delays
observation of their failure counters until a written status or STOP. Every
rolling capture, bank record, shield-cycle summary and relay report remains
mandatory. A non-divisible-stride Lua regression validates complete sample
coverage through STOP. Reported complete cycles now derive from observed
contiguous valid samples, not merely the requested tick limit.

Validation
----------
Seven focused SHA tests compare scalar, accelerated and automatic selection
against hashlib: boundary sizes, unaligned input, incremental writes, messages
larger than 1 MiB, arbitrary initial chaining states, concurrent initialization,
a hardware-disabled build and mocked missing CPU features with hardware code
still compiled. A standalone throughput benchmark varies input and consumes all
digest bytes; its timings are not substituted for the native measurements above.

The Linux Zig gate checker passed its synthetic scenarios, Lua bridge checks,
pinned-ELF checks and existing canonical world fixtures. These checks do not
prove gameplay or cross-machine determinism. Earlier 8520/8640-tick motion
failures remain open; a later diagnostic control passed 9000 ticks, so a short
pass cannot be interpreted as a fix for that timing-sensitive divergence.

The complete Python run after the changes discovered 1950 tests: 1923 passed,
27 were skipped and none failed. The project's strict checker correctly exits
nonzero for skips. An earlier intermediate run caught a transient test-header
formatting error while that file was being edited; its failed log is retained.
The clean rerun, rather than that intermediate result, describes the final tests.
The remaining skipped checks are not counted as passes.
Two of those skips were compiler-discovery configuration: after explicitly
setting X4LAN_ZIG, the NAT module build in both gates and C container codec
cross-check both passed in a focused rerun. The remaining 25 checks require
unavailable reference files or separate validation prerequisites.

An independent, default-off Linux ordered-pathing experiment is also compiled
into this candidate. Its first native attempt refused activation before any
rolling sample on both clients; that failure is retained. A pinned-ELF test
reproduced interference with the already installed agent-RNG call patch. The
arm check now normalizes only verified owned patches in a private byte copy
and still requires the original full-body SHA. Foreign patches remain refused.
Synthetic checks cover this interaction, complete batch execution and guarded
refusal; no performance comparison above enables the ordered mode. Native
acceptance of the correction is pending; it is not a motion-desync fix claim.

Graphics investigation
----------------------
RGB/white speckle artifacts were captured from the owned X4 window. They also
remain visible in a diagnostic run without the portable-math preload. That run
changes arithmetic and cannot be used as acceptance of the linux-core preset.
The checksum implementation had also changed while its bundle was built; its
exact binary is retained in that bundle. Disabling local render-ID allocation
also left the artifacts visible. More decisively, a fresh isolated creative
fixture without any native gate or portable-math preload still shows them.
This removes native lockstep hooks from that particular reproduction; fixture
MD and Lua autostart remain present, so it is not an unmodified gameplay test.

Further independent fresh-world checks changed only antialiasing 0 to the
current UI's canonical disabled value 'none', SSAO to 0, glow to 0, SSR to false,
or RADV_DEBUG=zerovram in the owned process environment. Each retained the
artifacts. A grouped check with AA=none, SSAO/glow/UI glow=0, SSR=false and
chromatic aberration=false produced a clean captured image. This narrows the
problem to that configuration or its interactions; it does not yet identify
a single cause. A subsequent check changed only chromatic aberration to false
and also produced a clean captured image. The private Linux test profiles now
disable that effect. This is a local graphics workaround, not a claim that the
engine or driver bug has been identified or repaired. All these captures saved
successfully, stopped their owned game and left the running Steam identity
unchanged. Normal graphics settings were not changed.
